# code-quality eval

## 평가 범위

- `trigger-cases.json`: 호출 여부 기대값입니다. 구조 검증 통과는 실제 모델의 호출 정확도를 뜻하지 않습니다.
- `code-quality.behavior.json`: 규칙을 적용한 판단을 평가하는 사례와 채점 기준입니다.
- `code-quality.results.json`: 실제 실행 결과입니다. 실행하지 않은 항목은 통과로 기록하지 않습니다.

## 행동 평가 재실행

1. 각 사례의 `request`만 새 평가 에이전트에 전달합니다. 기대 답인 `expect`, 이전 결과, 개선 의도는 제공하지 않습니다.
2. 프로젝트의 사용자 지침과 `code-quality/SKILL.md`, 필요한 규칙만 읽도록 합니다. 파일 수정과 외부 작업은 금지합니다.
3. 요청별 실제 답과 근거 규칙을 받습니다. 별도 검토자가 모든 `expect`를 만족하는지 읽고 채점합니다. 문구 일치나 키워드 유무로 채점하지 않습니다.
4. 실패하면 실제 답을 보존하고 해당 규칙만 고친 뒤 새로운 에이전트로 재실행합니다.
5. 결과에는 평가한 스킬 버전, 반복 수, 제공한 맥락, 한계를 기록합니다. 단일 실행 결과를 안정적인 성공률로 해석하지 않습니다.

수정 전후 비교 시 평가자는 각각의 규칙을 읽어야 합니다. 수정 전 규칙이 없다면 비교를
생략했다고 기록합니다. 파일을 동시에 수정하면서 읽히지 않도록 평가용 입력을 고정합니다.

## 구조 검증

프로젝트 루트에서 다음 명령을 각각 실행합니다:

```powershell
node scripts/codex/validate-skill-migration.mjs
node scripts/codex/validate-skill-yaml.mjs
```

이 명령은 모델을 호출하지 않습니다. 실제 호출 평가는 스킬 이름/description과 요청을
제공하고 스킬 선택 결과를 관찰해야 하며, 명시적으로 스킬을 읽으라고 지시한 행동 평가로
대체할 수 없습니다.
